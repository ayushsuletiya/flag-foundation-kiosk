Method: 9 area-scoped finder agents across correctness / performance / visual-UI-UX /
kiosk-robustness, **each finding then adversarially re-verified against the real code**
by an independent skeptic (38 agents total). 29 raw findings → **23 confirmed + 2
plausible**, 4 rejected as false positives.

were downgraded to HIGH by the verifier because CLAUDE.md §Pending explicitly defers

## HIGH (3)

### H1 · PNG-sequence turntables eagerly preload the whole sequence; carousel mounts up to 14 live players at once
`src/components/PngSequencePlayer.tsx:88` · performance · CONFIRMED · assets-media
The preload effect synchronously creates `frameCount` `Image()` objects in one loop and
holds the **entire** decoded sequence in RAM for the component's lifetime — no windowing.
Each live instance also runs its own rAF canvas clock. The carousel sets `mode="live"` on
every card, and once the ring is press-held into orbit the `!lifted → return null` cull no
longer fires, so all ~14 cards mount live players at once. `MAX_FRAMES=1024`.
**Failure:** client drops ~100-frame turntables (460×818 ≈1.5 MB decoded each); a visitor
press-holds to orbit → ~1400 concurrent decodes + 14 rAF loops → hundreds of MB spike and
dropped touch on the bandwidth-bound Arc iGPU. Dormant today (only `static.png` exists →
frameCount 0) but reachable via the documented turntable drop-in workflow.
**Fix:** live player only for the center card (sides `mode="still"` like the detail screen);
window/lazy-load frames around the current index; lower `MAX_FRAMES` (~240); pause rAF for
non-center cards.

### H2 · Renderer/GPU crash leaves the kiosk on a dead/black screen with no recovery
`electron/main.ts:86` · kiosk-robustness · CONFIRMED · electron
`createWindow()` registers only a `closed` handler — no `render-process-gone` /
`unresponsive` / `gpu-process-gone` / `child-process-gone`. A renderer or GPU crash does
NOT close the window (shows "Aw, Snap" or a black lost-WebGL canvas), so `window-all-closed`
never fires and `app.quit()` (the intended "let the OS watchdog restart us" path) is never
reached.
**Failure:** Arc GPU TDR reset during /chakra, or renderer OOM after hours of turntables →
window stays open on a dead canvas → kiosk bricked until power-cycled.
**Fix:** `webContents.on('render-process-gone', () => mainWindow?.reload())` + `unresponsive`;
`app.on('gpu-process-gone'/'child-process-gone', …)` → reload or `app.relaunch(); app.exit()`.
(Phase 7 scope, but small and high-value before onsite.)

### H3 · Default Electron menu accelerators are live in production (DevTools / reload / quit)
`electron/main.ts:91` · kiosk-robustness · CONFIRMED · electron
Never calls `Menu.setApplicationMenu(null)` nor a `before-input-event` swallow. With no
custom menu, Electron's default accelerators stay active even though `frame:false` +
`autoHideMenuBar` hide the bar visually: Ctrl+Shift+I / F12 open DevTools, Ctrl+R reloads,
Ctrl+W / Ctrl+Q / Alt+F4 quit — in the packaged build.
**Failure:** a USB keyboard on the exposed NUC opens DevTools over the exhibit or quits to
the Windows desktop.
**Fix:** `Menu.setApplicationMenu(null)` + `before-input-event` preventing control/alt/meta
and F5/F11/F12; DevTools off in packaged builds.

## MEDIUM (11)

### M1 · No top-level ErrorBoundary — any screen render throw permanently blanks the kiosk
`src/App.tsx:104` · kiosk-robustness · PLAUSIBLE · app-shell
Zero error boundaries anywhere (grep confirms). A render throw in any screen unmounts the
whole React root → permanently black `#000` screen, and App unmount tears down the idle-reset
listeners so it can't even self-recover.
**Failure:** client edits `content.xlsx` leaving a required row/field missing → a detail
screen indexes an empty array / reads a prop of `undefined` → throw → dead kiosk until reboot.
**Fix:** top-level ErrorBoundary wrapping `AnimatedRoutes` that logs, shows a safe state, and
auto-navigates home + remount-keys after a short delay.

### M2 · Quick Access overlay stays open across idle reset / programmatic navigation
`src/components/QuickAccessOverlay.tsx:236` · kiosk-robustness · CONFIRMED · app-shell / home-shared
*(Found independently by two finders.)* `isOpen` is local provider state rendered outside the
router; nothing closes it on a route change it didn't originate. The 120s idle reset
`navigate('/')` doesn't touch it.
**Failure:** visitor opens Quick Access on /chakra and walks away → idle reset returns Home
but the dark scrim + panel stay on top → next visitor lands on a dimmed modal, not a clean
attract screen.
**Fix:** in the provider, `const { pathname } = useLocation(); useEffect(() => setIsOpen(false), [pathname])`.

### M3 · Duplicate installation "#" id keeps both rows → React key collision + unreachable detail
`src/data/excelLoader.ts:322` · correctness · CONFIRMED · content-data
On a duplicate `#`, `parseInstallations` logs an error but still pushes the row and reuses the
id. Two Installations share an id.
**Failure:** client copy-pastes an installation row without renumbering → two identical React
keys; `expanded === row.id` matches both → both tiles expand/toggle together; detail routing
by id is ambiguous.
**Fix:** on `seenIds.has(id)`, assign a fresh fallback id (or `continue`) — never reuse.

### M4 · Workbook read without `cellDates` → date-typed cells render as raw serial numbers
`src/data/excelLoader.ts:634` · correctness · CONFIRMED · content-data
`read(bytes,{type:'array'})` has no `cellDates:true`; a Date-typed cell returns the numeric
serial (e.g. 37282), which `asString`/`asNumber` pass through verbatim — no date detection.
**Failure:** a "Year / Date" cell entered as `26 January 2002` that Excel coerces to a date
displays as `37282`.
**Fix:** `{type:'array', cellDates:true}` + handle `Date` in the coercers (format to display
string); defend text columns against serial-looking values.

### M5 · No single-instance lock — a watchdog restart / stray launch stacks a second kiosk window
`electron/main.ts:91` · kiosk-robustness · CONFIRMED · electron
No `requestSingleInstanceLock()`. NSIS is oneClick+runAfterFinish and Phase 7 wants
autostart/watchdog. A relaunch while the old instance lives creates a second fullscreen
`BrowserWindow`, overwrites `mainWindow` (orphaning the first), doubling GPU/IPC load and
breaking clean quit.
**Fix:** `requestSingleInstanceLock()` guard + `second-instance` → focus existing window.

### M6 · Rewind intro only probes `bg-1.png`, ignoring the `bg.mp4` / `bg.png` background forms
`src/screens/history/RewindIntro.tsx:97` · kiosk-robustness · CONFIRMED · history
Intro builds its year list probing only `background/bg-1.png`, but the documented convention
(and `historyAssets.ts`) also accept `bg.mp4` (wins) and single `bg.png`.
**Failure:** client delivers eras as single `bg.png` (or `bg.mp4`, the pending
`flag_timeline_assets` item) → intro finds 0 usable years → `usable.length < 2` → `finish()`
immediately, the marquee intro never plays (partial case drops some years).
**Fix:** reuse `historyAssets`'s candidate resolution (bg-1 → bg.png → mp4 poster); ensure the
last usable year equals `DEFAULT_HISTORY_YEAR`.

### M7 · Blank middle milestone shifts symbol stat cards into wrong-shaped slots
`src/screens/symbols/SymbolDetailScreen.tsx:197` · correctness · CONFIRMED · symbols
Milestones map POSITIONALLY onto four different-geometry slots (wide/small/small/wide), but
`parseSymbolIdentities` **filters out** blank cells, so a blank Milestone 2 collapses
`[M1,M3,M4]`.
**Failure:** client fills milestones 1/3/4 → M4 (often a big number for the wide bottom slot)
is squeezed into a small slot and shrunk; the wide bottom card renders empty.
**Fix:** keep a fixed-length-4 milestones array (push `''` for blanks) so index→slot alignment
tracks the original Milestone 1..4 columns.

### M8 · Symbol card ring (backdrop-filter panes + PNG players) remounts on every auto-advance
`src/screens/symbols/SymbolsCarouselScreen.tsx:341` · performance · CONFIRMED · symbols
At rest only 5 cards mount; the instant mode leaves `rest`, all ~14 render. Each is a real
`backdrop-filter` glass pane AND a PngSequencePlayer that re-preloads its whole frame set on
mount (no cross-mount cache). Auto-advance (3.5s) briefly mounts all 14 then collapses to 5.
**Failure:** with real turntables dropped in, every 3.5s → 14 backdrop-filters composite + 14
full re-decodes, torn down again → perpetual churn saturating the iGPU.
**Fix:** keep ring cards mounted but render distant cards cheaply (no backdrop-filter, paused
player beyond ±2), or cache decoded frames in PngSequencePlayer keyed by `srcPattern`.

### M9 · 260 ms hold-to-orbit threshold swallows normal touchscreen taps on side cards
`src/screens/symbols/SymbolsCarouselScreen.tsx:26` · kiosk-robustness · CONFIRMED · symbols
`onPointerDown` always arms a 260 ms orbit timer; a stationary press past 260 ms lifts the
ring, and release-without-drag gives spin≈0 → selection unchanged. `onClick` rotate is
suppressed once orbit engaged.
**Failure:** a visitor taps a side card but holds ~300–500 ms (typical on touch) → ring lifts,
they lift straight up → nothing happens; the carousel feels unresponsive.
**Fix:** raise threshold (~450–550 ms) and/or require a small movement before engaging orbit,
so a stationary press-release still rotates to that card.

### M10 · `rewindGL.dispose()` never calls `forceContextLoss()` — WebGL contexts accumulate
`src/screens/history/rewindGL.ts:275` · performance · CONFIRMED · history
`renderer.dispose()` frees programs/buffers but not the underlying context; it lingers on the
detached canvas until GC. Each History entry makes a fresh context, on top of the persistent
Chakra3D one.
**Failure:** over a museum day (enter History repeatedly) contexts pile toward Chromium's
~16-context cap → oldest (the chakra scene) force-evicted (wheel blanks) or new context creation
fails.
**Fix:** `renderer.forceContextLoss()` in `dispose()`.

### M11 · Bottom timeline year pills are fixed 177 px with no wrap — a 10th year overflows the bar
`src/screens/history/YearMainScreen.css:272` · kiosk-robustness · CONFIRMED · history
`.hy-pills` is a non-wrapping flex row of fixed 177 px pills in a 1765 px bar. 9 years fit with
~40 px slack; a 10th (=1896 px) overflows and is clipped by `overflow:hidden` — but years are
client-editable content.
**Failure:** client adds a `1906`/`1950` row → the newest pill spills past the bar and is
clipped/unreachable.
**Fix:** data-driven sizing (flex-shrink with min-width, or compute width from year count) like
the KnowMore strip already does.

## LOW (10)

### L1 · Map marker turntable frame count hardcoded to 60 instead of discovered
`src/screens/monumental/IndiaMap.tsx:107` · correctness · CONFIRMED · monumental
`MARKER_FRAME_COUNT=60` (only frame 1 probed), unlike symbols which discover the count.
**Failure:** client drops 90 frames → 61–90 never play (seam jump); 40 frames → 41–59 freeze
on frame 40 then snap. **Fix:** discover like `symbolsMedia`, or document the exact 60 in the
folder README.

### L2 · Poster removed on first *decoded* frame (not frame 0) → transient blank canvas
`src/components/PngSequencePlayer.tsx:94` · visual-uiux · PLAUSIBLE · assets-media
`status→'ready'` on `loaded===1`; poster unmounts, but rAF draws idx 0 and if frame 0 isn't
decoded yet it paints nothing. **Failure:** a later frame decodes first (parallel decodes) →
slot flashes empty for a few frames. **Fix:** flip to ready only once frame 0 loaded, or keep
poster until the first successful draw.

### L3 · Sunset PMREM environment texture leaks on every /chakra visit
`src/screens/chakra/Chakra3D.tsx:790` · kiosk-robustness · CONFIRMED · chakra
`scene.environment = pmrem.fromEquirectangular(t).texture` is never captured or disposed;
`dispose()` frees `envTex`/`pmrem`/`renderer` but not this output RT. Also the async loader
runs unguarded after teardown. **Failure:** hundreds of entries/day leak PMREM cubemap RTs →
GPU memory creep → context-loss risk over a multi-day run. **Fix:** capture and dispose the
texture; guard the callback with a `disposed` flag.

### L4 · First "Chakra in Flag" tap runs a 420-step cloth pre-warm synchronously on the main thread
`src/screens/chakra/Chakra3D.tsx:1261` · performance · CONFIRMED · chakra
`buildFlag()` does `for i<420: simulateCloth(...)` (~5–6 M constraint ops) synchronously inside
the mode effect. **Failure:** first flag-tab tap → ~20–40 ms hitch exactly as the dock camera
move begins. **Fix:** fewer pre-warm steps, or warm the flag during idle after boot so the
first tap only animates.

### L5 · Wheel always renders 24 tappable spokes; a `content.xlsx` with ≠24 virtues → dead spoke taps
`src/screens/chakra/ChakraExplorerScreen.tsx:168` · correctness · CONFIRMED · chakra
`virtues.find(v => v.spoke === spoke)` can be undefined; the wheel still eases/pulses the spoke
while the left column silently shows the intro. **Failure:** client saves 23 virtues → tapping
spoke 24 lights up but shows no content. **Fix:** ignore taps on spokes with no backing virtue;
clamp the interactive set to `virtues.length`.

### L6 · Home tile labels mapped to routes by array position, not by a key
`src/data/excelLoader.ts:186` · correctness · CONFIRMED · content-data
Tiles sorted by `#` and consumed positionally against fixed `HOME_TILES` routes; no slug/key
ties a label to a destination. **Failure:** client reorders the Home Menu rows → a label sits
on the wrong tile → visitor lands in the wrong section. **Fix:** match labels to routes by a
stable category key; validate all 4 categories present.

### L7 · KnowMore intro auto-fit `useLayoutEffect` has no dep array → forced reflow on every render
`src/screens/history/KnowMoreScreen.tsx:88` · performance · CONFIRMED · history
The auto-fit effect (intentionally dep-less for font swaps) runs after every commit, resetting
to 30px and reading offsetTop/Height in a loop. **Failure:** every gallery-thumbnail tap re-runs
up to 8 synchronous layout recalcs of the left column. **Fix:** key it on `[intro, heading,
row.year]` + a `document.fonts.ready` listener.

### L8 · Quick Access tiles crop photos in a ~2.7 % smaller box than the identical Home tiles
`src/components/QuickAccessOverlay.tsx:189` · visual-uiux · CONFIRMED · home-shared
Home tiles use `border:none` + a `::after` frame so percentage photo-crops resolve against the
full box; the overlay uses a real `3.736px` border → with `border-box`, the img's containing
block shrinks, shifting the crop (e.g. Ashok Chakra photo at `left:-35.82%/width:171.98%`).
**Fix:** mirror the Home `::after` inset-frame approach so the crop resolves against the full box.

### L9 · Cold-start default state "Odisha" is never reconciled with actual content
`src/screens/monumental/monumentalGeo.ts:258` · correctness · CONFIRMED · monumental
Initial `lastSelectedState='Odisha'` isn't checked against the client-editable installations.
**Failure:** client's Excel has no Odisha rows → cold start shows an empty list, zero markers,
and a gold "Odisha" chip — looks broken. **Fix:** if the initial state has 0 installations,
fall back to the first populated state.

### L10 · Monumental intro video has no timeout fallback for a stalled/non-terminating file
`src/screens/monumental/MonumentalIntroScreen.tsx:64` · kiosk-robustness · CONFIRMED · monumental
Auto-advance depends only on `onEnded`/`onError`; a muted-autoplay reject, decode stall, or
over-long file fires neither. **Failure:** a stalling `intro.mp4` freezes the intro until the
120s idle reset. **Fix:** a hard fallback timer (~8s) armed on mount, cleared on ended/tap.

## Rejected (false positives — verifier reasoning)

- **Hot-reload event dropped when a load is in flight** (`ContentContext.tsx`) — the
  early-return is real but the trigger is guarded by the main-process watcher's debounce.
- **Two symbol names collapse to one slug** (`symbolsData.ts`) — shipped `content.xlsx` has 14
  rows → 14 unique slugs, zero collisions.
- **Scrollable installation list stacks many backdrop-filters** (`MapExplorerScreen.tsx`) — list
  is filtered to one state; the 768 px viewport paints ≤6–7 collapsed tiles.
- **No navigation / window-open guard** (`electron/main.ts`) — real gap, but the renderer has no
  `window.open`, no `<a href>`, no untrusted nav source, so unreachable today.
